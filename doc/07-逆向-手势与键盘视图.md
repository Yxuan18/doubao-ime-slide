# 07 逆向：手势与键盘视图层

范围：`KeyboardView` 的触摸链路、豆包自带的手势能力、`nativeTouch` 的事件语义、
视图层级与坐标。源码路径均相对 `/tmp/doubao-ime/src/sources`；运行时证据来自
`/tmp/doubao-ime/*.log` 与模块 `ACCEPTANCE.md` 的真机记录。

**证据等级**：A = 运行时实测或直接读到的代码事实；B = 反编译源码可见、未运行时验证；
C = 推断（写明依据）。本文不引用任何截屏内容，只描述控件结构。

## 1. KeyboardView 的触摸链路

**1.1 入口顺序**（B，Android 语义 + 代码）：`View.dispatchTouchEvent` 先给
`OnTouchListener`，再进 `onTouchEvent`；`InputViewRoot` 在键盘视图上装了一个
转发监听器（`setupKeyboardCandidateTouchForwarding`，`com/bytedance/android/input/keyboard/areacontrol/InputViewRoot.java:2062`），
所以触点可能根本到不了 `onTouchEvent`。`onTouchEvent` 内部第一步是
`preHandleTouchEvent`（`KeyboardView.java:1296`），返回非 null 直接 return。

**1.2 `preHandleTouchEvent` 是早于 native 的接缝**（A 源码 + A 运行时：
`discover2.log` 每条 `[preHandle] DOWN … -> null`）。它做两件事：`l.g()` 为假时弹
「当前输入法无法使用」并返回 `TRUE` 吞掉整段事件；`mAsrLongPressView` 可见且键盘
不可见时把事件转给它（`KeyboardView.java:1484-1500`）。它还有第二个调用点：手写/
手写查字棋盘的空格键 `OnTouchListener` 会直接调它（`areacontrol/v0.java:31`）。

**1.3 `onTouchEvent` 的分支**（A 源码 `KeyboardView.java:1287-1342`）：

```java
if (action == 0) { delaySendLongPressMessage(x4, y5); ... }
else if (i11 == 5) { removeMessages(1); mMultiTouchOccurred = true; delay… }
else if (action == 6) { removeMessages(1); if (actionIndex == 0) return true; }
else if (action == 2) { if (mMultiTouchOccurred) return true; }
```

除 `action==6 && actionIndex==0` 外，所有事件最终都落到
`nativeTouch(mNativeViewId, x, y, action, 微秒时间)`。

**1.4 与触摸相关的字段**（A：`kv.log` 字段清单 + 源码）：

| 字段 | 作用 | 可否碰 |
|---|---|---|
| `mHandler`（`c extends qr0.b`，软引用持 view） | 唯一消息 `what==1` | 见 1.6 |
| `mMultiTouchOccurred` | 多指闸门；只在 UP/CANCEL 清 | 只读安全 |
| `mAsrLongPressView` | ASR 长按浮层，`preHandle` 转发 | 拦了 ASR 卡住 |
| `mFusiyinSingleBubble`（`popup.h`） | 上滑符号浮音气泡 | 纯显示 |
| `mListenerList`（`KeyboardView$d.a(int)`） | 可见性回调 | 安全 |
| `mNativeViewId` / `mWindowName` | 视图身份（见第 3 节） | 只读 |
| `mWidth/mHeight/mScale/mViewStretchScale` | 尺寸与比例 | 只读 |
| `mDirty/mBitmapBuffer/mCurrentCanvas/mLottie*` | 渲染 | 别碰 |

**1.5 与触摸相关的方法**（A 源码）：`delaySendLongPressMessage`(428)、`removeLongPressMessage`(1519)、
`nativeTouch`(676)、`preHandleTouchEvent`(1484)、`onSizeChanged`(1267)、`onMeasure`(1242)、
`updateScaleForHeight`(732)、`refreshScaleForCurrentSize`(1509)、`resizeView`(1523)、
`SetViewSize`(803)、`SetNativeId`(796)、`CreateView`(305)、`updateLocation`(1592)、
`onVisibilityChanged`(1347)、`onDraw`(1069)、`show/move/hideFusiyinSingleBubble`(711/652/622)、
`drawTouchTipBubble`(935)、`setListener`(1559)、`setAsrLongPressView`。

**1.6 Handler 消息只有一条**（A）：`MSG_LONGPRESS = 1`，500ms 后发
`nativeTouch(handle, x, y, -1)`（`KeyboardView.java:183-186`）。这就是 Java 侧
唯一的合成动作，也是运行时 `cancel1.log` 里 `[cancel] nativeTouch action=-1` 的来源。
第二根手指按下（action 5）会把这条计时器**重新武装**（1314-1316），不是取消。

**1.7 安全/危险分界**：

- **可安全拦截**：`nativeTouch`（终点转发，引擎状态完全由参数决定，模块现状）；
  `removeLongPressMessage`（幂等，只撤待发的 -1）；`KeyboardView$d` 可见性回调；
  浮音气泡三个静态方法。
- **拦了破坏引擎状态**：`nativeOnCreate/nativeOnSize/nativeOnScale/nativeOnLayout/
  nativeOnVisibleChanged/nativeDraw`（CPU 侧视图状态，`KeyboardView.java:661-676`）；
  `CreateView/SetNativeId`（身份，会拆掉 `sViewManager` 的键）；
  `TimerManager` 的消息回调（`TimerManager.java:28` 调 `KeyboardView.nativeTimerCallback`，
  这是引擎注册的定时器，不是 UI 动画）。
- **拦了破坏用户可见行为**：`preHandleTouchEvent` 返回非 null = 整块键盘失聪；
  `onTouchEvent` 返回 false = 事件交给父容器。

## 2. 豆包自带的其它手势能力

**2.1 光标拖动 / 移动光标模式**——两层，别混：

- Java 的 `com.bytedance.android.input.cursor` **不是**手势实现，是光标位置追踪器。
  `CursorMoveController` 把 `ShiftCursor(direction)` 翻成 DPAD 键事件：横向
  `-1→21（左）/ 其它→22（右）`（`CursorMoveController.java:644-661`），纵向
  `-2→19（上）/ 其它→20（下）`（同文件 687-711），带 `beginBatchEdit` 与选区几何，
  并在 `requestCursorUpdates(1)` 失败时降级（735-763）。调用它的只有
  `KeyboardJni.ShiftCursor(int)`（`KeyboardJni.java:1517`），而后者**没有 Java 调用者**
  ——是 native 回调进来的（B：无 Java caller；C：按 JNI 回调命名推断）。
- 真正的「模式」在 native：`ui::WindowBoardView::EnterMoveCursorMode(bool)` /
  `ExitMoveCursorMode` / `IsMoveCursorMode` / `IsMoveCursorModeSupported` /
  `ShouldExitMoveCursorModeOnRelease`（A：`nm -D libkeyboard.so`）。Java 桥是
  `enterMoveCursorMode()`、`exitMoveCursorMode()`、`isMoveCursorModeSupported()`
  （`KeyboardJni.java:5896/5900/6041`），回调 `onMoveCursorModeEntered/Exited`
  （4104/4120）。UI 入口两处：候选栏空闲区点击（`n7/a.java:746`）、工具箱第 16 项
  （`areacontrol/y.java:208`）。
- native 里还有一套滑动移光标：`ui::Slider`（RTTI `N2ui6SliderE`）、
  `DoSliderEvent cx:{}, cy:{}, threshold:{}`、事件名 `cursor_slide`/`cursor_slide_release`、
  `InputBoardLayout::GetSlideCursorThreshold` / `IsMoveCursorSlideExcludedControl` /
  `UpdateEdgeCursorSlideTimer`（A：`strings libkeyboard.so`；B：与空格键同段字符串，
  推断滑的是空格/棋盘）。**结论：拖动移光标已经存在，模块不该重造。**
- 复用三档：调 `enterMoveCursorMode()`（进 native 模式，风险最高）；反射 `ShiftCursor(int)`
  （static、内部判空，风险中）；自己走 `InputConnection.sendKeyEvent`（纯 Java，风险最低，
  但要自己处理组合区）。

**2.2 浮动键盘**——整窗移动，不是另一块棋盘。开关是 native `toggleFloatingWindow()`
（`KeyboardJni.java:6330`，由 `n7/a.java:563` 触发）；`setFloatingWindow(boolean)` 是
Java 静态方法，写 SharedPreferences `keyboard_is_floating_mode` 并重排布局
（`KeyboardJni.java:4754-4860`）；`InputView.setFloatingInputMode` 改 LayoutParams、
隐藏拖拽条、清 X/Y（`InputView.java:1063`）；拖动由 `drag_bar` 的 OnTouchListener
用 `getRawX/getRawY` 改 `setX/setY` 完成（`InputViewRoot.java:2900-3000`）。
注意 `KeyboardJni.isFloatingMode()` 读的是 `ImeService.n()` =
`InputView.J() && orientation==2 && f5914q`（`ImeService.java:1608`），即**横屏 + 开关**，
不是「用户把窗口拖起来了」。

**2.3 连续删除**——native 状态。`isKbdContinuousDeleting()` 是 native 实例方法
（`KeyboardJni.java:6037`；native 侧 `Jni_IsKbdContinuousDeleting`，日志
`is_continuous_deleting = {}`），**没有 Java 调用者**（B）。Java 侧真正执行删除的是
`KeyboardJni.backspaceClickEvent()`（1691）：处理选区、组合区、ASR 计数后经
`InputConnection` 删除，被 `BackspaceSwipeWindow` 的 50ms 重复消息调用
（`BackspaceSwipeWindow.java:125-135`）。上滑清空/下滑撤回是 native 判定、Java 画
：native 调 `KeyboardJni.OnBackspaceTouchEvent`(8 个 int)（1137），转给
`BackspaceSwipeWindow.g(action,x,y,eventTime,l,t,r,b)`（`BackspaceSwipeWindow.java:393`），
抬手再回 `doUpClearAction(1|2)`。**这条链路模块拿不到，除非 hook 那个 8 int 的静态回调。**

**2.4 双击空格**——分棋盘。`commitForSpaceDoubleClick(boolean,boolean)` 是 native
（`KeyboardJni.java:5856`），但 Java 侧 200ms 双击判定只写在手写/查字棋盘的 Java 空格键
里（`areacontrol/v0.java:104`、`InputViewRoot.java:585`），用的是 Java 自己画的
`SpaceButtonKeyComponent`。26 键主棋盘的空格由 native 绘制，双击句号应在 native 内完成
（C：主棋盘没有 Java 空格控件，`views.log` 树里也查不到）。模块不需要碰它。

## 3. 事件语义

**3.1 action 取值**：Java 显式处理 `0/1/2/3/5/6`，合成 `-1`；其余值走默认分支
原样转发（`KeyboardView.java:1339`，无白名单）。实测只见 `0/1/2`（`discover2.log`）
与 `-1`（`cancel1.log`）。`6`（ACTION_POINTER_UP）只在 `actionIndex != 0` 时到达
native，`actionIndex == 0` 被吞（1326-1329）。`4`（ACTION_OUTSIDE）在代码里没有任何
特殊处理，是否会到达取决于窗口 `setOutsideTouchable`，未证实（见第 6 节）。

**3.2 多指**：第二根手指是 `action=5`，不是又一个 0（A：源码 + 模块实测）；
`handle` 在整段多点事件里不变；`MOVE` 不带指针下标，`getX(actionIndex)` 只取当前
指针（A 源码 1290-1292）。因此 `mMultiTouchOccurred` 一置位，`MOVE` 全吞、只把
DOWN/POINTER_DOWN/UP 交给引擎。第二指按下还会重置长按计时器（见 1.6）。

**3.3 `handle` 什么时候变**：`mNativeViewId` 只在 `SetNativeId` 里被赋值，而
`SetNativeId` 只由 `CreateView(name, id, w, h)` 调用（`KeyboardView.java:305-321, 796`）。
`sViewManager` 是按**视图名**索引的静态表，运行时实测含 `soft_view`（1080×909，
`#7f110474`）和 `translate_view` 两个实例（A：`fields.log`）。所以 handle 会变的场景是
：native 对同一名字重新 `CreateView`（换棋盘/重建），或触点落在另一个命名视图上
（翻译模式）。**模块应按事件读 handle，不能缓存。**

## 4. 视图结构与坐标

**4.1 层级**（A：`views.log`，`uiautomator dump` 文本）：`DecorView [0,126 1080×2274]` →
`InputView [0,1401 1080×999]` → `InputViewRoot [0,1401 1080×999]` →
`LinearLayout(键盘区) [0,1401 1080×909]` → `RelativeLayout(id 0x7f0a0497) [0,1401 1080×909]`，
其下并列：`CandidateToolbarHostLayout [0,1401 1080×171]` 与
`KeyboardView [0,1401 1080×909] id=0x7f110474`。候选栏与键盘视图**同原点、同宽、
键盘更高**，且键盘被 `bringToFront()`（`InputViewRoot.java:3963`）——即键盘视图盖住
候选栏那 171px，靠 native 在这条带子里不画、再靠 OnTouchListener 把触点转发给候选栏
（B：方法名与调用点 `InputViewRoot.java:2062/3960`，方法体反编译失败）。
`InputView` 的 999 = 909 + 90（底部导航栏留白）；`translate_view` 是另一个 KeyboardView，
加在 `mBoardWhole` 顶部、高度 `InputViewModel.f8478j`（`InputViewRoot.java:3892-3930`，A/B）。

**4.2 放大/缩小时坐标怎么变**：`resizeView(w,h)` → `SetViewSize` → 改 LayoutParams →
`onSizeChanged` → `updateScaleForHeight(h)` → `nativeOnScale(id, scale, stretchScale)`
（`KeyboardView.java:1523/803/1267/732/796-801`）。native 按新高度重排所有键，
**视图内坐标原点不变**，比例变。窗口整体移动（浮动）只改 `getX/getY`，
`updateLocation` 用 `getLocationInWindow` 把全局偏移报给 `nativeOnLayout`
（1592-1600），不影响 `nativeTouch` 的局部坐标。模块每次 DOWN 读 `view.getHeight()`
重算是正确做法（现状如此）。

## 5. 对模块的可用性评估

| 候选扩展点 | 收益 | 风险 | 怎么验证 |
|---|---|---|---|
| `nativeTouch`（现状） | 引擎状态可完全推导，已跑通 | 扣 DOWN 会让 native 长按计时器不启动（已用 300ms 归还修掉） | ACCEPTANCE 已覆盖 |
| `preHandleTouchEvent` | 早于 `onTouchEvent` 的接缝，能在多指闸门之前拿到原始事件 | 返回非 null 直接让键盘失聪；手写棋盘上会被调用两次（`areacontrol/v0.java:31`） | hook 里只记录不返回，先在 26 键与手写棋盘各跑一遍，比事件条数 |
| `KeyboardJni.backspaceClickEvent()` | 现成的「引擎感知删除」：处理选区、组合区、ASR 计数 | 静态入口（项目硬约束禁止无实例调用）；无 InputConnection 时返回 false | 有选区/有预编辑/空输入三种状态各调一次，比对 `getTextBeforeCursor` |
| `enterMoveCursorMode()` / `ShiftCursor(int)` | 复用 native 光标模式，不用自己发 DPAD | 进入的是 native 模式，`ShouldExitMoveCursorModeOnRelease` 决定何时退出，模块若在中间吞事件可能卡在模式里 | 先只读 `isMoveCursorModeSupported()`；再进模式、退出、立即打字看组合区 |
| native 光标滑动（已存在） | 零成本 | 无（不碰） | 真机在空格上横向拖，观察光标移动 |
| `isKbdContinuousDeleting()` | 手势期间避让连续删除 | 低（只读 native 状态） | 长按退格时打日志看翻转时机 |
| `KeyboardView$d` 可见性回调 | 键盘隐藏时复位状态机 | 低 | 收起键盘后再弹出，检查是否残留 deferred |
| `SettingsConfigNext`（`btn_toolbar_move_cursor` / `one_hand` 等，`SettingsConfigNext.java:329`） | 只改配置就能决定工具栏暴露哪些能力，不必碰 native | 读的是本地 SharedPreferences 缓存（`d(String)`，414 行），引擎可能要 `ReloadConfig` 才生效；写坏键值会让工具栏少按钮 | 只读 `SettingsConfigNext.d("btn_toolbar_move_cursor")` 对比 UI；写入后看是否需要重启输入法 |

结论：**短期内只有 `preHandleTouchEvent`（旁路观测）与 `backspaceClickEvent`（删除动作）
值得试**；光标、浮动、连续删除、双击空格都是 native 能力，模块要么直接调 Java 桥，
要么别碰。用 `SettingsConfigNext` 改棋盘/工具栏是「改用户配置」，会落盘到 prefs。

## 6. 未证实

- `areacontrol/p.onTouch`（547 条指令）反编译失败：候选栏转发到底怎么判边界、
  返回 true 还是 false、是否会把事件继续交给 `onTouchEvent`，都不确定。若它返回 false，
  候选栏上的触摸会同时进 `nativeTouch`，模块的手势判定可能被候选栏点击污染。
- 候选栏/工具条区域的触点是否会出现在 `nativeTouch` 日志里——现有日志只测过键区，
  没有一条 y < 171 的 DOWN。
- 模块几何用的是 151/909 的顶部非键带，而 `views.log` 测得 Java 候选栏高 171；
  两者差 20px。是 native 自绘候选带与 Java 候选栏高度不同，还是测量态不同，未知。
- `cursor_slide` 到底是空格上的滑动，还是某一类 Slider 控件；`ui::Slider` 绑在哪个
  控件上没查到。
- 26 键主棋盘的双击句号是否全在 native（Java 侧只找到手写棋盘路径）。
- `handle` 在换棋盘后是否复用同一个值：只观测到两个实例，没观测到重建。
- action `4`（ACTION_OUTSIDE）与其它负值是否存在：代码无白名单，理论上会透传，无实测样本。
- `isFloatingMode()` 的横屏门槛与「窗口被拖动」之间的真实关系：Java 布尔量只反映
  开关 + 方向，没验证拖动后的取值。
