## 四、回退项：上滑输符号失效（2026-10-26 用户报告）

**现象。** 装模块之前，26 键上按住字母往上滑会打出该键上方标注的符号（C 上滑 `#`、
G 上滑 `(`）。装上第一版模块后，被映射的五个键上滑只打出一个字母。

**根因。** 第一版在 UP 时只补发一次合成轻点：`nativeTouch(handle, x, y, DOWN)` +
`nativeTouch(handle, x, y, UP)`。引擎靠相邻 MOVE 算方向，被压平成 DOWN+UP 之后只能
判成轻点，滑动的位移在补发时被丢掉了。

**修法。** 扣住 DOWN 的同时把后续每个 MOVE 的坐标、动作码、时间戳按序记进一个有界缓冲
（512 条，实测一次 164px 上滑产生 31 条），UP 时按原顺序把 DOWN + 全部 MOVE + UP 送回
`nativeTouch`。判定改成三段：超过 `FIRE` 触发快捷键；向下超过 `GATE` 且终点没有回到
起点上方则作废；其余（轻点、上滑、横滑）整段补发。

**验证。** 见 `ACCEPTANCE.md` 第三节 #14–#17。同一版代码下，被映射键的上滑符号回来了，未映射键的原生行为
没有变化，轻点与下滑快捷键都没有回归。

**标定（2026-10-26 晚间复测修正）。**

~~候选栏/组合区一出现，整块键盘会整体上移并改变键宽（1080×909 视图下，同一屏幕坐标
从 `字母=c` 变成 `字母=f`）。~~ **这段复现不出来。** 同一屏幕坐标 (540,1810) 在
「无组合」与「候选栏已出现」两种版面上各按一次 g，连测两轮，四次都是
`DOWN 540,409 view=1080x909 字母=g`；按 c 键两次也都是 `view=1080x909`。
视图尺寸不变，视图局部坐标也不变。当时的 `c → f` 更可能来自另一种版面
（工具条 / 英文面 / 不同键盘高度），或把屏幕坐标与视图坐标混用了。

**结论仍然成立、也必须照做**：任何用固定屏幕坐标做的手势测试，都要先用
`DOWN … view=… 字母=…` 这一行确认落键。屏幕坐标换算成视图坐标要减掉视图顶边
（本机 1401），而顶边本身会变——所以别缓存这个换算，每次都从日志里读。

## 五、修正项：多指误触发（2026-10-26 代码审查发现）

**现象。** 两根手指同时落在两个被映射键上（例如左手 A、右手 C），会莫名触发一次
全选或复制。审查时给的解释是「后一个 DOWN 重置了手势状态」，实测证明这个解释是错的，
真正的机制比它更隐蔽。

**实测的事件形态（等级 A）。** 用 `sendevent` 往触摸屏节点注入两指，再看引擎实际收到的
事件（`事件 action=… handle=…` 这一行）：

```
事件 action=0 handle=-5476376677671717424 104,408   ← 手指1 按 A
事件 action=5 handle=-5476376677671717424 431,629   ← 手指2 按 C
事件 action=1 handle=-5476376677671717424 431,629   ← 抬手，坐标是手指2 的位置
```

三条关键事实：

1. 第二根手指按下时引擎发的是 `action=5`（`ACTION_POINTER_DOWN`），**不是**又一个 0。
   所以「后一个 DOWN 重置状态」不成立——`onDown` 根本没被调用。
2. `handle` 在整段多点事件里是同一个值，**不能**用来区分指针。
3. `MOVE` 不带指针下标。第二根手指按下之后，任何一条坐标都可能属于另一根手指。

**根因。** `action=5` 落进了「其余事件」分支，被当成一次普通 MOVE 记进缓冲，
并且参与了位移计算：`dy = 629 - 408 = 221 > 60`，于是 UP 时按手指1 的字母触发了
`selectAll`。日志原文：`手势 a -> selectAll ok=true dy=221 (fire>60)`。

**修法。** 见到 `action=5` 就把这次手势标记为多指（`Gesture.multiPointer`）：
从那一刻起不再累计位移，UP 时跳过快捷键判定、整段补发。多指手势本来也不该触发
单字母快捷键，猜错的代价（一次莫名其妙的全选/复制）比不触发大得多。

**验证。** 见 `ACCEPTANCE.md` 第三节 #18–#20：同一注入脚本，改前误触发 `selectAll`，改后只补发；
两个字母都还在，没有丢字。

## 六、重构：判定抽成纯类（2026-10-26）

三处改动，全部落地并复测：

1. **排障日志改懒输出。** 16 处逐手势 `Log.i` 全部包进 `if (Log.DEBUG)`，`XposedEntry`
   的去重日志同样处理。交付构建里每一次触摸都不再写日志（第 25 项）。
2. **判定抽成 `GestureGate` 纯类。** 五段判定（PASS / CAPTURE / FIRE / DEAD / REPLAY）
   连同多指标记搬出 `SlideHook`，不碰反射、不碰 `View`，可以在 JVM 上直接测。
   `SlideHook` 只剩三件事：反射调用、扣事件、整段补发。
3. **两处静默降级改成显式。** `BoardGuard.install` / `SlideHook.install` 返回 `boolean`，
   `XposedEntry` 只装上一半时打一行 `模块未完整装配：…` 警告（且不撤标志，避免下一份
   ClassLoader 装出两套静态状态）；`BoardGuard` 对 `getCurrentKbdType` 先试
   `setAccessible(true)`，设不上就打警告而不是留到调用时才失败。

**红→绿证据（等级 A）。** 把 `GestureGate.onEvent` 临时改回 1.0.1 的行为（`action=5`
当普通 MOVE 处理、不设多指标记），测试立刻变红：

```
GestureGateTest > multiPointerNeverFires FAILED
    java.lang.AssertionError: 多指手势位移归属不可信，绝不能触发快捷键
    expected:<REPLAY> but was:<FIRE>
GestureGateTest > multiPointerBlocksDeadZoneToo FAILED
27 tests completed, 2 failed
```

恢复实现后 27 项全绿（`GestureGateTest` 16 项 + `GeometryTest` 11 项，
`./gradlew :app:testDebugUnitTest`）。这一对红绿锁的是第五节那个真机事故，
不是补写的装饰测试。

**设备侧回归。** 见第 21–25 项：轻点、上滑、死区、全选→复制→粘贴、数字面隔离、
